# 02. I/O Contract Design - 入出力契約の設計

LLM（大規模言語モデル）は、もともと人間と会話するために作られており、応答は自由形式の文章になりがちです。この文章をそのままアプリのコードで扱おう（正規表現で数値を抜き出す、など）とすると、LLMの言い回しが少し変わっただけで処理が壊れる、壊れやすい実装になりがちです。

これを防ぐ考え方が、SDKやWeb APIの設計で使われる「契約（Contract）」です。
契約とは、「何を渡せば何が返ってくるか」を事前に決めておく取り決めのことです。
LLM呼び出しでも同様に、入力（プロンプト）と出力（応答の形式）をあらかじめ決めておくことで、アプリ側のコードを壊れにくくできます。
これが本カテゴリで扱う**入出力契約（I/O Contract）** です。

LLM呼び出しの方式（01章）を決めたら、次はこの入出力契約の設計です。
このカテゴリでは、構造化出力（JSON）の契約設計、単発/バッチ呼び出しの使い分け、出力範囲の限定方法、複数ターンにわたる対話の設計を学びます。

## 学習目標

- JSON構造化出力の契約を設計できる
- 単発呼び出しとバッチ呼び出しを使い分けられる
- 出力範囲（フィールド・値域）をプロンプトで限定できる
- マルチターン（対話型）プロンプトを設計できる
