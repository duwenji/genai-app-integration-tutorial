# 03. Reliability & Cost - 信頼性・コスト最適化

LLM呼び出しは失敗する・重複する・遅い、という前提で設計する必要があります。
このカテゴリでは、防御的パース＋フォールバック、キャッシュ層、バッチ化・並列化、そしてLLM呼び出しのテスト方法を学びます。

「失敗する」とは、LLMが崩れたJSONを返す、CLIプロセスが応答なしのままフリーズする、ネットワーク瞬断でエラーになる、といった状態です。
「重複する」とは、同じ入力に対して何度もLLMを呼び直してしまい、そのたびに課金される状態を指します。
特にStreamlitはユーザー操作のたびに画面を再実行する仕組みのため、対策が無いと重複が起きやすい環境です。
「遅い」とは、応答が返るまで数秒〜数十秒かかるため、何も対策しないとその間アプリの操作全体がブロックされることです。
これらを放置すると、①パース失敗でアプリが落ちる、②タイムアウト無しで画面がハングする、③キャッシュ無しで想定外の高額請求が来る、という3つの実害に直結します。
以降の各教材は、この3つの実害を1つずつ防ぐ設計パターンを扱います。

## 学習目標

- 防御的パース＋フォールバックを実装できる
- タイムアウト・リトライ設計で一時的な失敗に対処できる
- キャッシュ層を設計できる
- バッチ化・並列化でコストを最適化できる
- LLM呼び出しをモック化してテストできる
